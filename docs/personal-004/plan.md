## Product contract

BullGod owns the personal identity, commitment and owner communication. A
specialist is optional help with one concrete sourced development. It is not a
replacement owner agent or a prerequisite for ordinary analysis.

Start from delivered news already retrieved through the approved reader. BullGod
may suggest specialist help; the owner reviews a concrete proposal naming the
registered target, question, exact shared sources and permitted output. Approval
is separate from the existing news-read grant and from publication permission.
Execution is one-shot. Verified results and source links return to the owner
conversation and remain linked to the commitment after restart.

The existing native `agent_delegate` intentionally creates an isolated worker
without target persistent context. The external named adapter is deliberately
restricted to fictional-record analysis. Leave those contracts unchanged. Use
the existing AgentBridge initializer for a fresh target-owned native session,
preserving target persona, memory and configured model. Empty tool schemas and
empty execution tools make this specific action source-only. Do not give the
native receiver a restricted-worker Authority object or BullGod's session.

## Implementation boundary

- Reuse the existing authenticated owner API, origin/source checks and native DB.
- Add a small research-action ledger beside commitments. Bind agent/session,
  commitment/revision, target public-profile/model/workspace fingerprint,
  immutable delivered source snapshots, question, output contract, expiry and
  one execution identity. Claim durably before initialization/model calls.
- Return stable action state for repeated clicks. Failed/uncertain work never
  automatically retries. Restart must preserve outcomes and expose abandoned
  execution as uncertain. Do not build another queue, daemon or controller.
- Preserve target-native task/result history. Export only validated source IDs,
  exact source excerpts and bounded classification/priority values to BullGod.
  Resolve citation URLs from the frozen inputs; reject invented IDs/quotes,
  extra fields, malformed/duplicate-key JSON and tool calls. This validates
  source provenance, not the publisher's claims or semantic truth.
- Extend the conversation attention UI to inspect/approve/deny/execute the
  concrete research proposal and explain unavailable, failed and completed work.
  An existing generic ask_specialist suggestion alone cannot authorize it.
- Use newest supported versions within each selected family for new defaults.
  Luna remains the routine role. Existing explicit model pins remain explicit;
  GPT5.6 is a manually selected last resort, never automatic fallback.

## Acceptance and gates

1. Fresh isolated instance, current Luna default, separate registered specialist
   profile/workspace/memory and no production private data or credentials.
2. Actual approved retrieval from https://tyl.ee/api/news; select a sourced
   development and ask BullGod whether specialist analysis would help.
3. Review named target, exact input and output scope. Denial/absence of approval
   must not execute. Approve one concrete task through owner controls.
4. Native registered specialist runs with its own identity/model/context and no
   tools. Verify source-bound result, native receipt and owner-facing explanation.
5. Repeat execute/reopen/restart without a second model call or lost outcome.
6. Show unavailable specialist and direct BullGod continuation with goal intact.
   Use deterministic negatives for expiry, changed target/revision, invalid
   citations, concurrent requests, timeout and abandoned execution.
7. Focused guarded tests, UI/200% checks, one independent authority review and a
   complete final-source local regression for the cross-module change. Preserve
   earlier valid evidence. Report hosted availability separately, without another
   control-plane investigation or changing CI protections.
8. Stop only owned processes, preserve fixtures/receipts, publish README and draft
   PR from codex/bullgod-personal-004 against master, and verify upstream0/0.
