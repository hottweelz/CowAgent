# BullGod computer-use capability matrix

## Scope and evidence method

This is a source inspection of the checked-out CowAgent tree. It separates native CowAgent features from optional MCP servers and experimental external-runtime code. The initial worker audit read source only: no service endpoint was called, no credential value or runtime state was inspected, and no test was run by that worker. A later lead observation of MCP configuration presence is listed below. Test names below are existing tests recommended for the parent harness to select; they are not test results.

## Conclusion

CowAgent has browser automation with a persistent, dedicated profile for external web-app cookies and a separate authentication path for its own console. It also has an optional Bearer-key HTTP chat API for CowAgent requests. These are distinct capabilities: the chat API does not control external apps. Browser automation is the native reuse path for external web-console tasks; general OS desktop control is not present in the inspected desktop bridge. MCP can add a computer-use server only when one is explicitly configured. The approval-gated CowAgent external adapter is a narrow experimental `analyze_records` path, not a general computer-use bridge. Source inspection cannot confirm the active install, browser readiness, live authentication, configured MCP roster, or runtime availability.

## Read-only installed MCP configuration observation

The lead inspected only MCP entry names/key presence in the persistent BullGod
configuration on 2026-11-15. `workspace/mcp.json` was absent; both
`config/config.json` and `data/config.json` had no top-level MCP keys or configured
`tools.mcp.servers` entries. No values from credentials, headers or environment
fields were printed. Native precedence is workspace `mcp.json`, then legacy
`mcp_servers` (`agent/tools/mcp/service.py:177-221`). Thus no configured
computer-use MCP backend was evidenced in these files. No server was started or
queried. This is disk configuration evidence, not a live in-memory tool roster.

## Native acceptance limit

The new profile fixture validates native local-file storage persistence and
profile separation. The isolated HTTP login experiment was not accepted: Chrome
navigation to its task-owned loopback server timed out, although Python could
reach the same server. Authentication to an external web app and persistence of
its cookies therefore remain source-supported capabilities, not runtime-verified
conclusions for this host. See `POC-RESULTS.md` for the precise result and blocker.
